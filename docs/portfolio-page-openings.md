# Give each page a reason to be visited

2026-09-11 — implemented for Mike's review.

## Brief and finding

Mike reported feeling lost on arrival at the background-check integration example. Its title named a technical domain and issued an instruction, but did not explain the relevance to a hiring reviewer. This is direct stakeholder feedback; no visitor study is claimed.

The goal is for a visitor arriving from any link to understand Mike's contribution, recognize the concrete example, and know what to inspect. Titles should carry the main capability; one short paragraph and a specific action should connect it to the artifact. Existing evidence qualifications stay visible. This refines the openings without reinstating decorative subtitle tiers.

## Decision

Lead with the work Mike does, then identify the case that demonstrates it. The alternative was to retain domain titles and add a separate "why you are here" explainer, which would leave the visitor to connect several text layers. A title alone would be shorter but would lose the example and its limitations.

- Role transformation: I redesign work around people, AI, and clear responsibility. Follow a sample role through the method Mike built.
- Enterprise delivery: I turn AI priorities into a plan teams can deliver. Inspect an approach to delivery, with working demos as supporting examples; do not imply measured enterprise deployment results.
- Feasibility: I use AI to surface what a build still needs. Compare recorded investigations as context changes.
- Controlled actions: I build AI workflows with checks before action. A fictional background-check workflow demonstrates an allowed update and a blocked write. The agent chooses tools; code checks responses and enforces the write rules.
- Advocacy: I make complex advocacy work easier for people to do. See how Mike designed the volunteer workflow, then try preparing testimony. This describes design intent, not measured volunteer outcomes.
- Skills: I make expert methods easier to reuse with AI. Try Design Planning, then inspect or install the published skill.

The agent menu labels now name the capabilities (AI feasibility investigation / AI actions with checks). The background-check example remains explicit in the opening paragraph. Recorded-demo controls describe the observable outcome; live tool labels remain unchanged.
